# «Живой листопад» — спецификация гибридной сборки

Версия 1.0 · сентябрь 2026 · рабочее название движка: **Живой экран**, сезон 1 — «Листопад»

---

## 1. Что делаем

Тот же принцип, что в «Снегопаде»: ребёнок раскрашивает бумажный лист с контуром кленового (дубового, берёзового…) листа, фотографирует по QR с телевизора — и его лист влетает в осеннюю сцену, где ветер гоняет листья по экрану. К зиме сцена меняет небо, контуры и физику — становится снегопадом. Движок один.

Схема гибрида:

```
                   БЕРЁМ ИЗ paper-aquarium (MIT)        ПИШЕМ САМИ
                   ─────────────────────────────         ───────────────────────────
Телефон            assets/capture.js — поиск меток,      страница загрузчика (UI вокруг
                   гомография, вырезание по контуру      capture.js), отправка на сервер
Листы раскраски    подбор кодов меток (алгоритм из       генератор листов из наших SVG
                   tools/make-coloring.js — переписываем контуров листьев, PDF
                   по логике, не копируем)
Сервер             —                                      комнаты, хранение, WebSocket,
                                                          лимиты, деплой на Railway
Сцена              —                                      three.js: листья, ветер, момент
                                                          появления, фон, накопление
```

Файл `LICENSE` автора кладём в папку `vendor/paper-aquarium/` рядом с `capture.js` — это единственное обязательство.

## 2. Что именно берём и как встраиваем

### 2.1 `capture.js` — контракт

Файл кладём как есть в `vendor/paper-aquarium/capture.js`. Он вешает на `window` объект `FishCapture` с одной функцией:

```js
FishCapture.processPhoto(source, manifest) → Promise<{
  kind,          // имя вида из манифеста ("maple")
  title,         // подпись вида
  texture,       // dataURL PNG 1024px — вырезанный рисунок по контуру, фон прозрачный
  preview,       // dataURL PNG — превью с белой обводкой контура
  boost          // ползунок «ярче цвета»: set(v), bake() → {texture, preview}
}>
// reject(Error) с понятным русским текстом: «не вижу метки…», «нужен лучший свет…»
```

`source` — `<img>`, `<canvas>` или `<video>`. Никаких зависимостей, работает на iPhone и Android в браузере. Обработка 1–3 секунды на телефоне.

Мы **не трогаем** этот файл. Всё, что он ждёт от нас, — правильный **манифест** (см. 2.2). Слово «fish» в его API нас не смущает: для него это просто «вид».

### 2.2 Манифест — что должно совпасть

`capture.js` читает из манифеста:

- `sheet` — геометрия листа A4 в мм: размер, положение и размер четырёх меток, рабочее поле. Берём значения автора без изменений (297×210 альбомный, метки 18 мм с отступом 8 мм, 6×6 клеток) — тогда точность распознавания уже проверена его автотестами.
- `fish[]` — массив видов, для каждого:
  - `name`, `title`
  - `markers.{tl,tr,bl,br}` — по 16 бит на угол. Коды должны отличаться между любыми двумя видами (с учётом поворотов) минимум на 4 клетки. Логику подбора (жадный перебор с расстоянием Хэмминга) переписываем сами в своём генераторе — это 40 строк.
  - `contourModel` — контур вида в «модельных» координатах, `bboxModel`, `sheetTransform {scale, ox, oy}` — как контур ложится на лист в мм. У автора контуры добывались из 3D-моделей; у нас источник проще — наш собственный SVG листа: берём path, дискретизируем в 80–120 точек, нормируем в bbox [-0.5, 0.5] по длинной стороне.
  - `eye` — у нас не нужен, оставляем пустым.

Итог: наш генератор `tools/make-sheets.js` читает `leaves/*.svg` и пишет `assets/coloring/manifest.json` + `assets/coloring/<вид>.svg` + `raskraski.pdf`. Сам `capture.js` при этом не узнаёт, что рыбы стали листьями.

### 2.3 Что НЕ берём и почему

- `server.js` — у автора файловое хранилище, пароли на аквариум, ТВ-код в памяти процесса. Нам нужны комнаты без паролей (см. 5), Postgres и WebSocket-рассылка нескольким экранам. Проще написать своё на 300 строк, чем вырезать половину его 1000.
- `demos/realistic-tank.html` — 3D-аквариум с рыбами на скелетной анимации, нам ничего оттуда не нужно.
- `index.html`, `modal.js`, `i18n.js` — UI и три языка; наш UI другой и пока только русский.

## 3. Листы раскраски

### 3.1 Виды (8 контуров, рисуем сами в SVG)

| Вид | Почему в наборе | Особенность контура |
|---|---|---|
| Клён | главный символ осени, самый узнаваемый | пять лопастей, крупные зоны для раскраски |
| Дуб | волнистый простой контур, легко детям | без острых углов |
| Берёза | маленький, зубчатый | делаем крупнее натурального, чтобы было что раскрашивать |
| Осина | почти круг | самый простой для малышей 3–4 лет |
| Липа | сердечко | второй простой контур |
| Каштан | одна доля (не вся «ладонь») | длинный, интересный для узоров |
| Рябина | одна долька | узкий, ложится в лист по диагонали |
| Ива | длинный узкий | для старших: узоры вдоль жилки |

На каждом листе: контур тонкой серой линией 1.6 мм (`capture.js` знает эту толщину и срезает полосу вдоль контура, иначе на текстуре остаётся тёмная кайма), пунктиром — центральная жилка (подсказка, не обязательная), подпись вида, строка «Имя: ____», маленький QR на сайт.

Одна страница = один лист. Пакет из 8 страниц в PDF, плюс отдельно «Клён и дуб» — 2 страницы, для тех, кому печатать много жалко.

### 3.2 Двусторонность

Лист в сцене кувыркается и показывает обе стороны. Изнанку не рисуем отдельно: берём ту же текстуру, чуть затемняем (−12% яркости) и уменьшаем насыщенность (−15%) — как реальный лист, у которого нижняя сторона тусклее. Дёшево и убедительно.

## 4. Сцена — three.js

### 4.1 Композиция кадра

- **Небо:** осеннее, высокое, светлое — тёплый градиент от бледно-голубого сверху к золотисто-серому у горизонта. Не закат (быстро приедается), а «ясный октябрьский день в 4 часа». Медленные полупрозрачные облака двумя слоями.
- **Дальний план:** силуэты голых деревьев и парковой аллеи, мягкий туман у земли.
- **Средний план:** одно-два дерева с ветвями, входящими в кадр сверху — с них «срываются» новые листья (см. 4.4).
- **Земля:** дорожка и трава, снизу экрана — ковёр из опавших листьев, который растёт (см. 4.5).
- **QR-карточка** в правом нижнем углу, **счётчик** в правом верхнем — как в снегопаде.

Настроение: иллюстрация к книге про осень, а не игра. Спокойно, тепло, дорого.

### 4.2 Лист как объёмное тело

Рисунок ребёнка — плоская текстура, но лист в сцене плоским быть не должен. Из текстуры делаем настоящий объёмный лист, а не бумажку:

**Геометрия.** Сетка 24×24 сегментов, обрезанная по контуру вида (вершины за контуром отбрасываются), поэтому у листа настоящие края, а не прозрачный квадрат. У листа есть **толщина**: две сетки — лицо и изнанка — сдвинуты на 0.6 мм и замкнуты по контуру полоской; на крупном плане виден край с торцом, как у настоящего листа.

**Форма покоя (по виду).** Каждый вид имеет свой профиль изгиба, зашитый в конфиг: клён выгнут куполом с приподнятыми кончиками лопастей, дуб волнистый по краю, берёза почти плоская с загнутым кончиком, ива свёрнута лодочкой вдоль жилки, у каштана приподнятые края. Плюс сухость: чем «старше» лист (случайный параметр 0–1), тем сильнее края скручены к изнанке — как у листа, полежавшего на солнце. Это и есть ответ на «края листочков изгибаются»: у каждого листа они изогнуты по-своему, статически.

**Живая деформация (в вершинном шейдере, дёшево для сотни листьев):**
- Изгиб под аэродинамической нагрузкой: лист гнётся против набегающего потока пропорционально `dot(normal, v_rel)`, сильнее у краёв, слабее у жилки — жилка жёсткая, ткань между жилками мягкая (карта жёсткости строится один раз из контура и центральной линии: чем дальше от жилки и черешка, тем мягче).
- Флаттер: по краю бегут мелкие волны с частотой, зависящей от скорости потока (как трепещет лист на ветру) — амплитуда растёт от жилки к краю.
- Кручение вокруг жилки при боковом порыве — половинки листа расходятся по фазе.
- Изгиб непрерывно меняет нормали (пересчёт в шейдере через производные), поэтому освещение реагирует на каждую волну.

**Материал и свет — где рождается «объём»:**
- Физически корректный материал: шероховатость 0.55, лёгкий блик — лист матовый, но не пластик.
- **Просвет (translucency).** Главный приём: когда лист оказывается между солнцем и камерой, свет проходит сквозь него, и рисунок ребёнка светится насыщенно, как витраж. Реализуется как обратный лэмберт с картой толщины (у жилки лист толще — светится меньше). Именно этот эффект даёт «дорогую» картинку.
- Изнанка чуть светлее и матовее лица (реальные листья), подкрашена в сторону серо-жёлтого, а не просто затемнена.
- Рельеф: из рисунка ребёнка автоматически строится карта нормалей (по яркости) — штрихи фломастера читаются как мелкий рельеф, лист перестаёт быть гладкой картинкой.
- Тени: листья отбрасывают мягкие тени на землю и друг на друга (shadow map 2048, мягкий PCF); лежащие в ковре — с контактной тенью.
- Лёгкая глубина резкости: дальние листья мягче, крупный план резкий — сцена читается как кино, не как игра.

Размер в сцене — по виду: осина 0.8, берёза 0.9, клён 1.4, каштан 1.6, ива 1.5×0.4.

### 4.3 Физика полёта

Лист — не точка и не плоскость, а лёгкое гибкое тело с распределённой массой. Модель — твёрдое тело с аэродинамикой, рассчитанной по нескольким точкам поверхности; изгиб из 4.2 подстраивается под результат, поэтому картинка и физика не расходятся.

**Поле ветра** — сумма трёх составляющих, трёхмерное (есть составляющая к экрану и от экрана — листья приближаются и удаляются, а не летают в одной плоскости):
1. **Фон** — горизонтальный вектор 0.3–1.5 м/с, направление ±20° от «слева направо», меняется раз в 20–40 с.
2. **Порывы** — каждые 8–25 с проходит фронт шириной 30% сцены, до 4 м/с, 2–4 с. После порыва — затишье, планирование. Это ритм сцены.
3. **Вихри** — 1–2 дрейфующих вихря (3D curl noise); листья идут по спирали, раз в несколько минут один усиливается на 5 с.
4. **Восходящие потоки** над «тёплой» дорожкой — слабые, но из-за них некоторые листья зависают и снова поднимаются.

**Движение одного листа** — состояние `{pos, vel, quat, angVel}`, тензор инерции плоской пластины, центр масс сдвинут к черешку на 10–15%:
- Поверхность листа представлена **9 опорными точками** (центр, 4 вдоль жилок, 4 у края). В каждой точке считаем относительную скорость воздуха, давление `∝ ρ·|v_rel|²·|dot(n, v̂_rel)|` и силу вдоль нормали. Сумма сил — сопротивление и подъёмная сила сразу, без отдельных формул; сумма моментов относительно центра масс — вращение.
- Отсюда сами, без ручных правил, получаются все режимы падения, известные для листьев: **планирование зигзагом** (маятник), **кувырок** (tumbling — лист вращается вокруг длинной оси и уходит вбок), **спиральный спуск** (когда центр давления смещён), **штопор** у длинных узких листьев (ива). Какой режим выпадет — зависит от формы, «сухости» и начального толчка, поэтому два одинаковых листа падают по-разному.
- Изгиб под нагрузкой (4.2) меняет эффективную площадь: сильно согнутый лист теряет подъёмную силу и ускоряется — так ведёт себя настоящий лист в порыве.
- Угловая скорость гасится квадратично по сопротивлению воздуха — кувырок затухает, лист выравнивается и снова планирует.
- Земля: столкновение с мягким контактом — лист касается, пружинит на миллиметры, ложится по рельефу ковра (нормаль к поверхности) и постепенно теряет остаточное покачивание. Сильный порыв может снова поднять лежащие листья (сначала приподнимает край — это видно — потом отрывает).
- Столкновения листьев между собой в воздухе не считаем (дорого и незаметно); в ковре — только чтобы не проваливаться друг в друга.

Интегратор — полунеявный Эйлер с подшагами 4 на кадр, детерминированный по seed (для отладки). Всё считается на CPU: 120 листьев × 9 точек — около 0.5 мс на кадр.

**Уровни детализации.** Два режима:
- **Крупный план** (момент появления, «найти лист», галерея): полная ткань — сетка листа моделируется как ткань на пружинах (Verlet, 24×24 узла) с жёсткими жилками, ветер действует на каждый узел. Лист по-настоящему мнётся, край трепещет, кончики загибаются от порыва. Один лист за раз — это дёшево.
- **Общий план**: твёрдое тело + шейдерный изгиб из 4.2, параметры изгиба берутся из тех же сил. Переход между режимами бесшовный — в момент выхода из крупного плана состояние ткани сворачивается в позу твёрдого тела.

Параметры физики и материалов — в `seasons/autumn.json`, dev-панель крутит их в реальном времени, чтобы подобрать поведение на глаз.

### 4.4 Момент появления

1. По WebSocket приходит `leaf.new`. Ближайшие 5 с — очередь.
2. 0–0.7 с: на ветке дерева в верхней части кадра появляется новый лист (масштаб 0 → 1), качается на черешке.
3. 0.7–1.5 с: «отрывается», камера (виртуально — просто увеличиваем лист) даёт крупный план ~30% высоты экрана в центре, лист медленно кувыркается, показывая обе стороны. Подпись: **«Лист Артёма»** (шрифт рукописный). Мягкий звук — шорох листвы.
4. 1.5–4.0 с: крупный план держится, вокруг несколько маленьких листьев-«искр» в тёплых тонах.
5. 4.0–5.0 с: лист уменьшается до сценического размера и его подхватывает порыв — уносит в общий поток. Порыв в этот момент запускается принудительно, чтобы появление заканчивалось движением.
6. Счётчик +1.

### 4.5 Накопление

- Ковёр внизу собран из реальных пользовательских листьев — лежащие листья видны, их можно найти взглядом. Максимум 60 лежащих, при переполнении самые старые «уходят под верхние» (fade и удаление).
- Каждые 10 листьев — ковёр на 1% выше, максимум +12%.
- Сезонный ход: в сентябре деревья на среднем плане с листвой (текстура), к концу октября — голые; листва на деревьях — отдельный спрайт, прозрачность по дате.

### 4.6 Производительность

- До 120 летящих + 60 лежащих листьев. Текстуры всех листьев — в **одном атласе** 4096×4096 (ячейки 512 px → 64 листа на атлас, атласов до 4), сетки листьев одного вида — в одном инстансированном меше с UV-смещением и параметрами изгиба на инстанс. Итог — один draw call на вид, 8 на всю сцену, плюс проход теней.
- Полная ткань (Verlet) — только у одного листа в крупном плане; остальным изгиб считает шейдер.
- Просвет, карта нормалей и тени — по умолчанию включены; на слабом ТВ автоматически отключаются тени и глубина резкости (замер fps первые 5 секунд).
- Текстуры с телефона (1024 px PNG) на сервере ужимаются до 512 px WebP для атласа; для крупного плана берётся оригинал 1024 px. Там же на сервере из текстуры один раз строятся карта нормалей и карта толщины.
- Цель: 60 fps на ноутбуке, 30 fps на Smart TV 2020+. Если ТВ не тянет WebGL 2 — fallback на упрощённый режим: 40 листьев, без изгиба в шейдере.

### 4.7 Панель настроек

Как в снегопаде: звук, сила ветра (штиль / ветерок / буря), галерея всех листьев с именами, «найти лист», QR крупно, полноэкранный режим, dev-панель с параметрами физики (скрыта за `Shift+D`).

## 5. Сервер

### 5.1 Стек

**Node 20 + Fastify + ws**, **PostgreSQL** (Railway), файлы — Railway volume (потом Cloudflare R2). Обработка изображений — `sharp` (ресайз, WebP, сборка атласа). Один сервис, статика сцены и загрузчика раздаётся им же.

Вся тяжёлая работа с фото уже сделана на телефоне в `capture.js` — сервер получает готовый PNG с прозрачным фоном. Это сильно упрощает бэкенд по сравнению со спецификацией снегопада: OpenCV не нужен.

### 5.2 Модель данных

```
rooms      id, code (LEAF-7K3P), owner_token, season ('autumn'|'winter'), created_at, last_seen_at
leaves     id, room_id, kind, name, tex_url, thumb_url, atlas_slot, author_token, created_at, deleted_at
```

Комната создаётся без регистрации с экрана телевизора. `owner_token` в cookie сцены даёт право удалять и сбрасывать; `author_token` в cookie телефона — удалять свои листья. Паролей нет — всё необратимое привязано к устройству, на котором комнату создали, а восстановление владения — через простой «код владельца», который показывается один раз при создании.

### 5.3 API

```
POST /api/rooms                          → {code, owner_code}
GET  /api/rooms/:code                    → {season, leaves: [...]}         (сцена при загрузке)
POST /api/rooms/:code/leaves             → multipart {texture(png), kind, name} → {id, tex_url, atlas_slot}
DELETE /api/rooms/:code/leaves/:id       → author_token или owner_token
POST /api/rooms/:code/reset              → owner_token
GET  /api/manifest                       → манифест листов (для capture.js на телефоне)
GET  /api/sheets.pdf                     → раскраски
WS   /ws/rooms/:code                     → события leaf.new, leaf.deleted, room.reset
```

Лимиты: 200 листьев на комнату, 60 загрузок в час с адреса, 3 МБ на текстуру. Комната живёт 90 дней с последней активности.

---

## 6. Загрузчик (телефон)

Одна страница `/r/:code`:

1. «Сфотографировать лист» → камера (`<input capture>`).
2. Обработка через `FishCapture.processPhoto(img, manifest)` прямо на телефоне — 1–3 с. Ошибку распознавания показываем его же текстом (он уже человеческий: «все четыре чёрных квадрата должны быть в кадре»).
3. Предпросмотр: лист кувыркается на фоне неба (маленькая three.js-сцена или просто CSS 3D-поворот), ползунок «Ярче цвета» — это `boost.set()` из capture.js.
4. Имя автора → «Отправить в листопад» → `boost.bake()` → POST.
5. «Летит! Посмотри на телевизор», «Мои листья».

## 8. План (с Клод Кодом)

| Этап | Что делаем | Приёмка |
|---|---|---|
| **1. Листы и распознавание** (3 дня) | 8 SVG-контуров, `make-sheets.js` с подбором кодов, манифест, PDF; `test-capture.html` | Все 8 листов распознаются в тесте с перекосом до 25° и шумом; 20 реальных фото — ≥ 18 удачных |
| **2. Сцена без сервера** (4 дня) | Небо, деревья, земля, физика ветра, порывы, вихри, ковёр; клавиша N — тестовый лист из PNG | Смотрится 30 минут, не надоедает; листья ведут себя как листья, не как конфетти |
| **3. Сервер + комнаты + WS + атлас** (2 дня) | API из 5.3, сборка атласа при добавлении | curl-ом отправленный PNG появляется в сцене за < 4 с |
| **4. Загрузчик** (2 дня) | Страница вокруг capture.js, предпросмотр, отправка | Ребёнок 6 лет проходит путь с подсказкой родителя |
| **5. Момент появления, галерея, панель** (2 дня) | 4.4, 4.7 | Есть «рилс-момент» |
| **6. Деплой на Railway, домен, инструкция для ТВ** (1 день) | Docker, HTTPS, страница «4 способа вывести на телевизор» | Работает с телефона и Smart TV вне локальной сети |
| **7. Обкатка в 3–5 семьях** (1 неделя) | Сбор проблем, правки | Замер «от печати до листа на экране» |

Порядок сознательно начинается с этапа 1: распознавание — это то, что мы берём чужое, и надо на первом же шаге убедиться, что оно работает с нашими контурами. Дальше — только своё.

Итого: три недели до рабочей версии; октябрь — обкатка и контент; в ноябре собираем зимний конфиг на том же движке.
