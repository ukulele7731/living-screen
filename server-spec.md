# «Живой экран» — сервер, комнаты, роли, бот. Спецификация этапа 3

Версия 2.0 · сентябрь 2026 · заменяет разделы 5 и 7 в `leaffall-hybrid-spec.md`.

Что изменилось относительно версии 1: российский хостинг вместо Railway, объектное хранилище вместо диска, три роли вместо двух, привязка телевизора кодом с экрана, Telegram-бот как личный кабинет, гербарий, срок хранения год, бэкапы. Сервер с первого дня лежит в отдельной папке `server/` и не переплетается с остальным кодом — в декабре он уедет в приватный репозиторий.

---

## 1. Принципы

1. **Без регистрации.** Комната создаётся с экрана телевизора одним нажатием. Никаких почт и паролей на входе.
2. **Телефон ничего не набирает, телевизор — тем более.** Гость попадает по QR, телевизор привязывается кодом, который вводят на телефоне.
3. **Кабинет владельца — Telegram-бот.** Там код, пароль, уведомления, гербарий. Веб-версия кабинета — потом, если понадобится.
4. **Один движок — много сезонов.** Поле `season` в комнате решает, какая сцена и какие контуры. Листопад, снегопад, ёлка, машинки — конфиг, не код.
5. **Детские рисунки — это чужое.** Хранить бережно, удалять честно, бэкапить обязательно.

## 2. Роли

| Роль | Как попадает | Что может |
|---|---|---|
| **Экран** | Открывает сайт, видит код привязки, владелец вводит его на телефоне | Только смотрит. Экранов у комнаты сколько угодно |
| **Гость** | По QR с экрана | Добавляет листья, видит «мои листья», удаляет только своё |
| **Владелец** | Создал комнату (cookie) или ввёл код комнаты + пароль | Всё: удаляет любой лист, сбрасывает, меняет сезон и настройки, привязывает экраны, получает гербарий |

Гость и владелец — это токены в cookie/localStorage телефона. Пароль нужен владельцу только на новом устройстве. Пароль показывается один раз при создании, крупно, с кнопкой «скопировать» и кнопкой «отправить в Telegram».

## 3. Комнаты

- Код: `LEAF-7K3P` — префикс сезона + 4 символа из алфавита без похожих (нет 0/O, 1/I). Около миллиона кодов на сезон; при исчерпании — пятый символ.
- Пароль владельца: 6 символов из того же алфавита, генерируется, можно сменить в боте.
- Создание: `POST /api/rooms` с экрана. Ответ: код, пароль (один раз), токен владельца (в cookie), код привязки этого экрана (сразу привязан).
- Лимиты создания: 5 комнат в час с адреса, 20 в сутки. Комната без единого листа удаляется через 24 часа.
- Живёт **год** с последнего листа. За 30 дней до удаления — сообщение в бот с гербарием и кнопкой «продлить».

### 3.1 Привязка телевизора

1. Телевизор открывает `zhivoy.ekran/tv` (короткий адрес, читается с экрана). Видит крупный четырёхзначный код привязки и QR.
2. Владелец на телефоне (в боте или на сайте) вводит этот код → телевизор привязан. Cookie на телевизоре хранит токен экрана.
3. Код привязки живёт 10 минут, хранится в Redis. Один код — один экран.
4. В настройках комнаты — список экранов («Телевизор в гостиной», «Планшет») с кнопкой отвязать.

Если телевизор почистил cookie — открывает `/tv` снова, получает новый код, владелец вводит. Тридцать секунд.

### 3.2 Сезон

`season` в комнате: `autumn` сейчас, `winter` в декабре. Смена сезона — действие владельца в боте: сцена на экране перезагружается с новым конфигом, старые листья остаются в гербарии, в новой сцене не летают.

## 4. Модель данных (PostgreSQL)

```
rooms
  id, code UNIQUE, season, password_hash, owner_token_hash,
  settings JSONB (звук, сила ветра, ...), tg_chat_id NULL,
  created_at, last_leaf_at, expires_at

screens
  id, room_id, token_hash, label, user_agent, last_seen_at, created_at

leaves
  id, room_id, kind, name, author_token_hash,
  tex_key, thumb_key, orig_key NULL, normal_key, thick_key,
  atlas_slot, created_at, deleted_at NULL

pairing_codes  (Redis, TTL 600с)  code → {screen_token, room_id NULL}

events (для статистики, без персональных данных)
  id, room_id, type, at
```

Всё, что можно потерять без последствий (коды привязки, счётчики лимитов), — в Redis. Всё, что нельзя, — в Postgres.

## 5. Хранение картинок

Объектное хранилище S3-совместимое (у Timeweb Cloud / Selectel есть, оплата российской картой). Бакет `living-screen`, приватный, доступ через сервер по подписанным ссылкам.

На один лист:

| Файл | Размер | Срок |
|---|---|---|
| `tex` — 512 px WebP, с альфой по маске контура | ~60 КБ | год |
| `thumb` — 128 px WebP | ~5 КБ | год |
| `normal`, `thick` — карты нормалей и толщины 512 px | ~40 КБ | год |
| `orig` — 1024 px PNG как пришёл с телефона | ~400 КБ | 7 дней, потом удаляется |

Ключи: `rooms/{code}/leaves/{id}/{tex|thumb|normal|thick|orig}.{ext}`.

Оценка: семья за сезон — 30–50 листьев, ~5 МБ. 10 000 семей — 50 ГБ, ~150 ₽/мес.

### 5.1 Обработка при загрузке (sharp)

1. Принять PNG от телефона (уже вырезанный capture.js, фон непрозрачный, «вытянутые цвета»).
2. Наложить маску по `contourModel` вида с эрозией 2 px внутрь и мягким краем 1 px → альфа.
3. Ужать до 512 px WebP — `tex`. 128 px — `thumb`.
4. Карта нормалей из яркости (Sobel, сила 0.6), карта толщины: 1 у жилки → 0.4 у края.
5. Записать в хранилище, в базу, выделить слот атласа, разослать `leaf.new` по WebSocket.

Всё вместе — меньше 400 мс.

## 6. API

```
POST   /api/rooms                              → {code, password, screen_pairing_code}
GET    /api/rooms/:code                        → {season, settings, leaves[]}   (экран при загрузке)
PATCH  /api/rooms/:code                        → season, settings              (владелец)
POST   /api/rooms/:code/reset                  →                               (владелец)
POST   /api/rooms/:code/login                  → {password} → owner cookie     (новое устройство)

POST   /api/rooms/:code/leaves                 → multipart {texture, kind, name} → {id, tex_url, atlas_slot}   (гость)
DELETE /api/rooms/:code/leaves/:id             → своё (гость) или любое (владелец)
GET    /api/rooms/:code/leaves/mine            → листья этого телефона

GET    /api/tv/pairing                         → {code}                         (экран без комнаты)
POST   /api/rooms/:code/screens                → {pairing_code} → привязать     (владелец)
GET    /api/rooms/:code/screens                → список экранов                 (владелец)
DELETE /api/rooms/:code/screens/:id            →                                (владелец)

GET    /api/rooms/:code/herbarium.png          → коллаж всех листьев            (владелец)
GET    /api/rooms/:code/herbarium.zip          → все текстуры + json            (владелец)

GET    /api/manifest?season=autumn             → манифест контуров для capture.js
GET    /api/sheets.pdf?season=autumn           → раскраски

WS     /ws/rooms/:code                         → экран подписывается токеном экрана
         события: leaf.new {id, tex_url, kind, name, atlas_slot}
                  leaf.deleted {id}
                  room.reset
                  room.season {season}
                  room.settings {settings}
```

Лимиты: 200 листьев на комнату, 60 загрузок в час с адреса, 3 МБ на текстуру, 20 символов имя. Всё с понятными русскими ошибками.

## 7. Telegram-бот

Один бот на все сезоны. Название — под общее имя продукта, не «листопад».

### 7.1 Привязка к комнате

- На экране после создания комнаты — QR «Открыть кабинет в Telegram» (`t.me/бот?start=LEAF-7K3P-<одноразовый токен>`). Владелец сканирует → бот привязан к комнате как владелец, без пароля.
- Или вручную: `/start` → «Введи код комнаты и пароль».
- У одного чата может быть несколько комнат (дом, дача, бабушка). `/rooms` — список, переключение.

### 7.2 Что умеет

| Команда / кнопка | Что делает |
|---|---|
| Уведомления | «Маша добавила лист 🍁» с миниатюрой. Включаются/выключаются. Не чаще одного сообщения в 5 минут — если пришло пять листьев подряд, одно сообщение «5 новых листьев» с коллажем |
| Листья | Список последних с миниатюрами, удалить любой |
| Экраны | Список, привязать новый (ввести код с ТВ), отвязать |
| Настройки | Сила ветра, звук, сезон |
| Раскраски | Прислать PDF под текущий сезон |
| Гербарий | Сгенерировать сейчас (коллаж) — см. раздел 8 |
| Пароль | Показать / сменить |
| Помощь | Как вывести на телевизор — 4 способа |

### 7.3 Автоматические сообщения

- Через час после создания комнаты, если ни одного листа: «Раскраски здесь, а вот как снять на телефон» — ссылка на PDF и минутное видео.
- Через 7 дней тишины: одно напоминание с миниатюрами последних листьев. Больше не повторять.
- Конец сезона (для осени — 1 декабря): гербарий и «а хочешь снегопад?».
- За 30 дней до удаления комнаты: гербарий + «продлить».

### 7.4 Техника

- Библиотека `grammy` (Node), webhook на наш сервер, тот же процесс.
- `tg_chat_id` в `rooms`. Бот никогда не хранит переписку, только команды.
- Все тексты — в `server/bot/texts.ru.json`, не в коде.

## 8. Гербарий

Коллаж всех листьев комнаты за сезон: листья с мягкими тенями на кремовом фоне, у каждого подпись именем автора и датой, сверху — название («Наш листопад, осень 2026»), внизу — код комнаты мелко. Формат: 2480×3508 (A4 300 dpi) для печати и 1080×1920 для сторис.

Генерируется на сервере (sharp + SVG-шаблон), по запросу из бота и автоматически в конце сезона. Кэшируется до следующего листа.

Зимой такой же «снежный альбом» может стать платным — архитектура одна.

## 9. Публикация — что открыто, что закрыто

Проект открытый сейчас, закрывается к зиме. Чтобы это было одним движением:

- `server/` — самодостаточная папка со своим `package.json`, никаких импортов из `scene/` или `uploader/`. Общее — только формат манифеста и событий WS, описанный в `docs/protocol.md`.
- В декабре `server/` переезжает в приватный репозиторий как есть, в открытом остаются сцена, загрузчик, контуры, инструменты и протокол.

## 10. Хостинг и развёртывание

**Timeweb Cloud** (или Selectel — устройство одинаковое):

| Что | Тариф | Цена/мес |
|---|---|---|
| VPS 2 ядра / 2 ГБ / 40 ГБ, Ubuntu 24 | минимальный | ~600–900 ₽ |
| PostgreSQL как сервис (или в докере на том же VPS для старта) | минимальный | 0–500 ₽ |
| Объектное хранилище S3 | по объёму | ~150 ₽ на 50 ГБ |
| Домен `.ru` | год | ~300 ₽ |

Docker Compose на VPS: `app` (Node: API + WS + бот + статика), `postgres`, `redis`, `caddy` (HTTPS автоматически, вместо Traefik — проще конфиг). Один файл `docker-compose.yml`, один `.env`, деплой — `git pull && docker compose up -d --build`.

Статика сцены и загрузчика раздаётся тем же Caddy из папки `dist/`, собранной в CI. GitHub Pages остаётся для демо-версии без сервера.

### 10.1 Бэкапы

- Postgres: `pg_dump` каждую ночь → в объектное хранилище, папка `backups/`, хранить 30 штук. Скрипт в `server/ops/backup.sh`, запуск по cron внутри контейнера.
- Хранилище: включить версионирование бакета — случайно удалённый файл восстанавливается 30 дней.
- Раз в месяц — проверка восстановления на пустой базе (скрипт `restore-test.sh`), результат в бот админу.

### 10.2 Мониторинг

- `/healthz` — база, Redis, хранилище.
- Бот админу (отдельный чат): падение сервиса, ошибка бэкапа, ежедневная сводка — комнат живых, листьев за сутки, экранов онлайн сейчас, ошибок распознавания.

## 11. Страницы сайта (тексты — отдельно)

## 12. План этапа 3

| Шаг | Что | Приёмка |
|---|---|---|
| 3.1 | Папка `server/`, Fastify, Postgres, Redis, Docker Compose, `/healthz` | Поднимается локально одной командой |
| 3.2 | Комнаты, роли, токены, привязка экрана, лимиты | Тесты на все три роли и все отказы |
| 3.3 | Загрузка листа: маска, sharp, хранилище, атлас, WS | Лист из curl виден в сцене < 4 с, в двух экранах одновременно |
| 3.4 | Бот: привязка, уведомления, листья, экраны, раскраски | Полный путь из бота без сайта |
| 3.5 | Гербарий | Коллаж за 3 с на 200 листьев |
| 3.6 | Бэкап, мониторинг, `docs/protocol.md` | Восстановление из бэкапа на пустой базе |
| 3.7 | Деплой на VPS с доменом, HTTPS | Работает с телефона по мобильному интернету |

Примерно 5–6 рабочих дней Клод Кода. Домен, VPS и токен бота нужны к шагу 3.4.
