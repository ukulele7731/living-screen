# Развёртывание: VPS, домен, первый вход

Часть 1 — арендовать сервер и домен (можно сделать заранее, до шага 3.7).
Часть 2 — поставить сервер (шаг 3.7, команды появятся там).

Названия кнопок в панели Timeweb Cloud время от времени меняются; ищите по смыслу.

## Часть 1. Сервер и домен в Timeweb Cloud

### 1. Регистрация и оплата

1. Открыть https://timeweb.cloud → «Регистрация». Нужны почта и телефон.
2. Войти в панель. Слева меню: «Облачные серверы», «Домены», «Баланс» и т. д.
3. «Баланс» → «Пополнить» → 1 000 ₽ (хватит на сервер и домен на первое время).
   Российская карта или СБП. Списание за сервер идёт посуточно, деньги не пропадают.

### 2. Создать сервер

1. «Облачные серверы» → «Создать» (или «Добавить»).
2. Операционная система: **Ubuntu 24.04**. Без панелей управления и без предустановленного ПО.
3. Регион: Москва или Санкт-Петербург, любой.
4. Конфигурация: самая маленькая — **1 CPU, 1–2 ГБ памяти, 30–40 ГБ диска NVMe**.
   Ориентир 300–500 ₽ в месяц. Больше не нужно.
5. Сеть: **публичный IPv4 — обязательно** (обычно включён по умолчанию). IPv6 не нужен.
6. Резервные копии от Timeweb: **включить**, если предлагают (около 10% от цены сервера).
   Это страховка на случай поломки диска — внутри детские рисунки.
7. Название сервера: `living-screen`. Проект: любой.
8. Способ входа: если спрашивают про SSH-ключ — пропустить, вход будет по паролю.
9. «Заказать» / «Создать». Сервер готов через 1–2 минуты.

После создания открыть страницу сервера и записать:

- **IP-адрес** (четыре числа через точку, например `185.xx.xx.xx`);
- **пароль root** — показан на странице сервера («Доступ», «Учётные данные») или пришёл на
  почту. Сохранить в надёжном месте, в чат не присылать.

### 3. Домен

Вариант А — свой домен `.ru` (примерно 300 ₽ в год):

1. «Домены» → «Зарегистрировать» → ввести желаемое имя (например `zhivoy-ekran.ru`) →
   если свободно, «Заказать».
2. Заполнить данные владельца. Для зоны `.ru` регистратор обязан спросить паспортные данные
   физлица — это требование правил зоны, не Timeweb.
3. Оплатить. Домен появляется от нескольких минут до пары часов.
4. Открыть домен → «DNS-записи» (или «Настройки DNS») → добавить две записи типа **A**:

   | Тип | Имя (хост) | Значение |
   |---|---|---|
   | A | `@` | IP-адрес сервера |
   | A | `www` | IP-адрес сервера |

   Если Timeweb предлагает «привязать домен к серверу» одной кнопкой — можно ей, она делает
   то же самое.
5. Записи разъезжаются по интернету от 10 минут до нескольких часов.

Вариант Б — временный домен для проверки. На странице сервера у Timeweb часто есть бесплатный
технический адрес вида `xxxx.tw1.ru` (раздел «Сеть» или «Домены»). Для шага 3.7 и первых
проверок его достаточно; свой домен можно купить позже, тогда просто поменяем одну строку
в настройках.

### 4. Первый вход на сервер — без установки программ

1. Страница сервера → кнопка «Консоль» (веб-терминал в браузере).
2. Появится чёрное окно с `login:` — набрать `root`, Enter, затем пароль (при вводе пароля
   символы не показываются — это нормально), Enter.
3. Если увидели строку вида `root@living-screen:~#` — вы на сервере.

Проверка, что всё живое (набрать и нажать Enter):

```
uname -a
```

Ответ начинается с `Linux` — хорошо.

### 5. Подготовить сервер (один раз, 5 минут)

Скопировать в консоль по одной строке, после каждой ждать окончания:

```
apt update && apt -y upgrade
```
```
curl -fsSL https://get.docker.com | sh
```
```
apt -y install git ufw
```
```
ufw allow OpenSSH && ufw allow 80 && ufw allow 443 && ufw --force enable
```
```
docker --version && git --version
```

Последняя команда должна напечатать версии Docker и git. Если что-то ответило ошибкой —
скопировать текст ошибки в чат.

### 6. Что прислать в чат

- IP-адрес сервера;
- домен (свой или технический `xxxx.tw1.ru`), если уже есть.

Пароль root, данные карты и паспорта — никогда.

## Часть 2. Установка «Живого экрана» на сервер

Один раз, в консоли сервера (по одной команде). Домен здесь — `живой-экран.рф`, в punycode
`xn----8sbepkhizex5l.xn--p1ai`; для другого домена подставить свой.

```
git clone https://github.com/ukulele7731/living-screen.git /opt/living-screen
```
```
cd /opt/living-screen && git checkout claude/stage-3-server && cd server && cp .env.example .env
```
(папка `server/` появляется только после переключения ветки; дальше все команды — из неё)
```
sed -i 's#^NODE_ENV=.*#NODE_ENV=production#; s#^PUBLIC_URL=.*#PUBLIC_URL=https://xn----8sbepkhizex5l.xn--p1ai#; s#^SITE_ADDRESS=.*#SITE_ADDRESS=xn----8sbepkhizex5l.xn--p1ai#; s#^CADDY_HTTP_PORT=.*#CADDY_HTTP_PORT=80#; s#^CADDY_HTTPS_PORT=.*#CADDY_HTTPS_PORT=443#' .env
```
```
docker compose up -d --build
```
```
docker compose ps && curl -s https://xn----8sbepkhizex5l.xn--p1ai/healthz
```

Ожидается: оба контейнера `running`, ответ `{"ok":true,...}`. В браузере: https://живой-экран.рф/healthz.

Обновление после новых коммитов (и после любой моей правки — это же и есть «выкатить исправление»):

```
cd /opt/living-screen/server && git pull && docker compose up -d --build
```

Логи: `docker compose logs -f app` (выход — Ctrl+C). Остановить: `docker compose down`
(папка `data/` с базой и рисунками остаётся).
