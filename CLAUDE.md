# «Живой экран» / сезон 1 — «Живой листопад»

Ребёнок раскрашивает бумажный лист с контуром (клён, дуб, берёза…), фотографирует
его по QR с телевизора — и лист влетает в осеннюю three.js-сцену, где ветер гоняет
листья по экрану. Зимой тот же движок становится снегопадом: меняется только конфиг
сезона и набор контуров.

Документы проекта (читать перед любой работой):

- `leaffall-hybrid-spec.md` — спецификация: **что** делаем.
- `leaffall-build-guide.md` — пошаговая инструкция: **что нажимать и в каком порядке**.

Проект открытый, лицензия MIT. Язык интерфейса и документации — русский.

## Структура папок (раздел 7 спецификации)

```
living-screen/
  vendor/paper-aquarium/      capture.js + LICENSE (MIT, автор Мистер Мотя) — сторонний код
  leaves/                     наши SVG контуров листьев, 8 файлов
  tools/make-sheets.js        SVG → листы раскраски + manifest.json (наш код)
  tools/make-pdf.js           листы → raskraski.pdf (headless Chrome)
  tools/test-capture.html     прогон всех листов через capture.js с перекосом/шумом
  assets/coloring/            результат генератора: <вид>.svg, manifest.json, raskraski.pdf
  server/                     Fastify, БД, WS, атлас — изолированная серверная часть
  scene/                      Vite + three.js: sky, trees, leaf, wind, intro, ground, ui
  uploader/                   мобильная страница /r/:code
  seasons/autumn.json, winter.json   параметры сезона: небо, физика, набор видов, тексты
```

Сезон — это конфиг, а не ветка кода.

## Жёсткие правила

1. **`vendor/paper-aquarium/capture.js` не изменяем никогда.** Это сторонний код под MIT,
   лежит как есть вместе с `LICENSE` автора. Если распознавание не работает — чиним
   свой манифест и свои листы, а не его. Не форкать, не «чуть подправить», не копировать
   куски в свой код. Алгоритм подбора кодов меток из авторского `tools/make-coloring.js`
   переписываем по логике сами, не копируем.
2. **Идём по этапам раздела 8 спецификации, не забегая вперёд.** Один этап — одна
   сессия. Не начинать следующий этап, пока не пройдена приёмка текущего. Не делать
   «всё сразу по спецификации». После каждой удачной проверки — коммит
   `этап N: что сделано`.
3. **Серверная часть изолирована в `server/`.** В декабре она будет вынесена в отдельный
   приватный репозиторий. Поэтому `server/` не импортирует код из `scene/`, `uploader/`,
   `tools/`, и наоборот — никто не импортирует из `server/`. Общий контракт между
   ними — только HTTP/WS API из раздела 5.3 спецификации и формат `manifest.json`.
   Свои зависимости, свой `package.json`, свой Dockerfile — внутри `server/`.

## Контракт capture.js (что он читает из манифеста)

`window.FishCapture.processPhoto(source, manifest) → Promise<{kind, title, titles, texture, preview, boost}>`.
Слово «fish» в его API — просто «вид»; для нас это лист.

Поля манифеста, которые capture.js реально читает:

- `sheet.w`, `sheet.h` — размер листа в мм (297×210, альбомный).
- `sheet.marker.size` — сторона метки в мм (18). Число клеток 6×6 зашито в код.
- `sheet.markerPositions.{tl,tr,bl,br}` — `[x, y]` левого верхнего угла метки в мм
  (авторские: tl [8,8], tr [271,8], bl [8,184], br [271,184]).
- `sheet.work` — `{x0, y0, x1, y1}` рабочее поле в мм (36..261 × 36..166): по бумаге
  вокруг рисунка считается баланс белого.
- `fish[].name` — идентификатор вида (возвращается как `kind`), `fish[].title` — подпись,
  `fish[].titles` — необязательный словарь по языкам.
- `fish[].markers.{tl,tr,bl,br}` — по 16 бит (внутренние 4×4 клетки метки; внешнее
  кольцо всегда чёрное). `0` = чёрная клетка, `1` = белая. Поиск точный, без коррекции
  ошибок, все 4 поворота каждого кода регистрируются в одной таблице — коды всех видов
  и углов должны различаться с учётом поворотов на 90°.
- `fish[].contourModel` — замкнутый полигон, массив точек `[z, y]` в модельных
  координатах: `z` — горизонталь, `y` — вертикаль **вверх**.
- `fish[].bboxModel` — `{z: [min, max], y: [min, max]}` контура (поле `x` не читается).
- `fish[].sheetTransform` — `{scale, ox, oy}`: точка модели ложится на лист как
  `x_mm = ox + scale·z`, `y_mm = oy − scale·y` (ось y переворачивается).
- `fish[].eye` — не читается, оставляем пустым.

Наши дополнительные поля в `fish[]` (capture.js их не читает, читают сцена и генератор):
`vein` — центральная жилка `[[z,y],[z,y]]` в модельных координатах, `rotate` — поворот листа
на странице от вертикали (градусы по часовой стрелке), `fit` — доля рабочего поля под габарит.

Важно: `texture` на выходе — **непрозрачный** PNG шириной 1024 px, кадр по `bboxModel`.
Внутри контура — рисунок ребёнка, снаружи — «вытянутые» цвета края и средний цвет.
Обрезка по контуру делается тем, кто рисует лист (сцена по `contourModel`), а не capture.js.

## Этап 1: листы и распознавание — как пользоваться

```
node tools/make-sheets.js        # leaves/*.svg → assets/coloring/{<вид>.svg, manifest.json, sheets.js}
```

- Исходники контуров — `leaves/<вид>.svg`: один замкнутый `<path>` (кубические Безье, без дуг
  и `transform`), кончик вверх, черешок внизу, плюс необязательная `<line id="vein">`.
- Поворот и fit каждого вида — в `SPECIES` внутри `tools/make-sheets.js`. Рабочее поле
  225×130 мм, поэтому длинные листья кладём почти горизонтально (rotate 80–90°); генератор
  предупреждает, если ширина самого листа на бумаге меньше 60 мм, и подсказывает лучший угол.
  Вертикально стоят только клён, липа, осина — они всё равно упираются в высоту поля (122 мм).
- Проверка толщины: контур на бумаге растеризуется с шагом 0.5 мм и открывается диском 8 мм.
  Всё, что при этом пропадает и выступает дальше 5 мм, — тонкий элемент (черешок, острый
  кончик, перешеек); генератор пишет предупреждение с видом, толщиной и местом. Зубцы и
  скруглённые углы не считаются. Кончики делаем тупыми (угол ≥ 60°) или скруглёнными.
- Ось y: в SVG вниз, в модели capture.js вверх. Инверсия делается один раз в
  `buildModelTransform`, дальше все координаты модельные.
- `assets/coloring/sheets.js` — тот же манифест плюс строки SVG, чтобы `tools/test-capture.html`
  работал с `file://` (там fetch запрещён). Генерируется, руками не править.
- PDF: `node tools/make-pdf.js` → `assets/coloring/raskraski.pdf` (8 страниц: клён, дуб, липа,
  осина, берёза, каштан, рябина, ива) и `raskraski-mini.pdf` (клён и дуб). Печать через headless
  Chrome (`CHROME_PATH`, иначе ищется сам), `@page 297mm 210mm, margin 0`. После сборки скрипт
  разбирает PDF сам (zlib, без зависимостей), находит чёрные квадраты меток, декодирует их
  коды и сверяет центры и расстояния с манифестом: расхождение больше 0.5 мм — ошибка.
- Тест: открыть `tools/test-capture.html` в браузере. Каждый лист снимается «телефоном»
  (наклон до 25°, поворот, вверх ногами, шум, размытие, серые метки на жёлтой бумаге) и
  прогоняется через `FishCapture.processPhoto`. Внизу — «Провалов: N из M».
- Срез по краю: печатный контур 1.6 мм + срез capture.js 1.8 мм с каждой стороны, итого у
  рисунка теряется около 2.6 мм по краю. Тонких перешейков и черешков уже 10 мм не рисуем.

## Этап 2: сцена — как устроена

```
cd scene && npm install && npm run dev      # http://localhost:5173
npm run build && npm run preview            # сборка в scene/dist
npm run typecheck
```

- **Задник — нарисованная картина** `scene/public/backdrop.jpg` (2992×1684): небо, аллея,
  деревья с листвой, скамейки, земля. Она заменяет процедурные небо, дальний план, туман и
  землю (их первая версия осталась в истории, коммит c8270a1). Картина не проходит через
  освещение и ACES: 3D-слой рендерится на прозрачном фоне, проходит тонмаппинг и sRGB в
  `OutputPass`, и в `src/composite.ts` накладывается поверх картины в sRGB.
- **Совмещение с картиной**: `backdrop.horizon` в `seasons/autumn.json` — доля высоты картинки,
  где точка схода аллеи; камера наклоняется так, чтобы её горизонт попал туда же. Картинка
  масштабируется по принципу cover, при широком экране обрезается сверху/снизу вокруг горизонта.
- **Живое небо**: маска неба строится при загрузке из картинки (голубые и белые пиксели внутри
  `backdrop.skyRegion`, эрозия + размытие), в композите по маске плывут процедурные облака.
  Проверить маску: `?mask=1`. Отключить облака: `?clouds=0`, тени: `?shadow=0`.
- **3D-слой сейчас**: свет (`lighting.ts`: солнце впереди-слева по картине, hemisphere),
  ветка среднего плана (`midTrees.ts`: процедурные сучья из цилиндров, один меш, тени),
  невидимая земля-приёмник теней (`ground.ts`, ShadowMaterial, y = 0). Листья, ветер и
  физика — следующие части этапа 2.
- **Солнце впереди камеры** (азимут −28°, высота 11°), как на картине: это нужно для просвета
  листьев (4.2). Тени от 3D-объектов ложатся к камере.
- Скриншот в контейнере: headless Chromium с SwiftShader (программный WebGL) — fps там
  бессмысленны, смотреть draw calls и треугольники в dev-оверлее (клавиша H).
